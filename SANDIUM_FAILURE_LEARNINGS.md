# SANDIUM Failure Learnings

## 2026-10-18 — Stage 2 GN generation fails on missing Brave vendor dependency

### Evidence

Pipeline #24 `stage-2-graph-and-compile-window` failed during `generate-ninja-files`:

```text
ERROR at //brave/components/brave_wallet/browser/BUILD.gn:506:5:
Unable to load "/home/circleci/project/src/brave/vendor/bat-native-tweetnacl/BUILD.gn".
```

The same run confirmed GN is resolvable and that `generate-ninja-files` was reached. It did not show a compiler or Siso remote-execution failure. `REMOTE_CACHE_LOG_MATCHES=NO_MATCHING_LINES` is not the root cause.

### Root cause

Stage 1 intentionally moves the whole `src/brave` checkout out of the cache before saving the Chromium-only `src` tree. Stage 2 restores the Chromium tree and checks out tracked Brave Core source, but that fresh Git checkout does not restore the DEPS-managed working copies under `src/brave/vendor`. The missing `bat-native-tweetnacl` directory is therefore consistent with the cache boundary, not with the Chromium source cache being corrupt.

`src/brave/build/version.gni` is also generated by Brave's DEPS hook, so manually generating that one file is not a sufficient fix for all generated/vendor inputs.

### Corrective change

Stage 2 now has a `Rehydrate Brave Core DEPS and run hooks without refreshing pinned Chromium` step before GN:

1. Runs `ci/siso/chromium_pin.py --require-reusable`. If the restored Chromium checkout, commit, version-file hash, `.gclient` hash, or source manifest does not match the manually approved pin, the step fails closed before invoking sync.
2. Runs Brave's normal `pnpm run sync --target_os=android --target_arch=arm64 --no-history --sync_chromium=false`. The explicit false flag prevents a Chromium update; the Brave sync path is run to restore Brave Core's own DEPS, and hooks run because `--nohooks` is not passed.
3. Verifies that the Chromium commit and tag are unchanged, the `.gclient` content hash and source manifest still match, `src/brave/vendor/bat-native-tweetnacl/BUILD.gn` exists, and `src/brave/build/version.gni` exists before proceeding to GN.
4. Records explicit pass/failure markers so another missing dependency is reported in source preparation, not as an unexplained GN failure.

### Validation

- Commit: `e56c89a14dfadfdd122ba3d85fea870e68409ddd`
- Validation workflow: https://github.com/sandeepbimt/Sandium/actions/runs/39140068993

- This validation did not start an APK build. The next five-stage CircleCI run must still prove that the Brave DEPS sync produces the required inputs and GN proceeds.

## 2026-10-20 — Stage 1 remote-execution gate stopped before a reusable handover

### Evidence

The failed Stage 1 job had 6,959 Siso action records and zero uncached remote
worker completions. It spent 1,561 seconds in stage preparation before the
compile window, then the 240-second early gate interrupted the build. At
shutdown, the Siso filesystem-state file was absent while its journal remained,
so the usual checkpoint handover could not be saved.

The metrics JSONL contained remote-cache spans such as exec-remote-cache-check
and exec-remote-cache-run. This proves the remote-cache path was exercised, but
it does not prove a fresh worker completed an uncached action. The available
logs do not establish why the worker action was not recorded.

### Corrective change

- Explicitly export SISO_CREDENTIAL_HELPER and test its credential protocol
  without printing the API key.
- Before the full Chromium compile, run one salted, strict-remote C++ action.
  Require an uncached remote result for the exact test-only object and a
  complete nonempty Siso state/journal pair.
- Store a marker in the Chromium output checkpoint bound to workflow ID, Brave
  commit, Chromium commit, and tag. Later stages validate and reuse that proof;
  they do not repeat the probe.
- Let the full build use the separately validated preflight proof to avoid a
  false negative caused by delayed first remote completion. Report full-build
  remote metrics separately from the preflight action.
- At Stage 1 startup, verify the same-revision APK cache before source sync so
  an already verified APK can skip all setup work.

### Validation criteria

The GitHub trigger workflow runs syntax checks and targeted regression tests
before calling CircleCI. The five-stage workflow proceeds to the full compile
only if the isolated current-workflow probe proves an uncached remote C++
action. A green APK result remains unconfirmed until a real APK is produced
and independently verified.
